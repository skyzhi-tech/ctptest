# CTP 程序化交易测试指南

[项目首页](../README.md) · [快速开始](quickstart.md) · [常见错误与 SDK 边界](troubleshooting.md)

ctptest 内置以下 29 个测试点，面向 CTP 开平撤单、连接监测、控制与错误处理的证据核验。表中的编号是项目内部标识，不代表期货公司统一的测试规范；界面使用测试名称。无需额外文档即可了解每项行为与准备条件。

## 测试前准备

先完成 [账号及 Token 配置](quickstart.md)，等待 SDK 登录同步完成及交易日就绪。使用专用模拟或仿真环境，避免其他客户端同时操作相同合约而改变持仓或冻结数量。ctptest 直接使用用户买入价／卖出价，不依赖行情。

## 持续报单与非法输入证据

持续报单默认每秒一笔、持续 6 分钟，频率配置不得低于已确认的生产阈值每秒一笔，时长须超过 5 分钟。首尾时点都发送，默认计划 361 笔请求；不突发补单来掩盖频率不足。按实际发送时间计算频率，每个子单须有唯一关联及明确柜台回报。每 10 秒显示进度，结束显示汇总；回报超时只能标为待核对，不能直接宣称丢单或测试通过。

有效未成交挂单不等于堵单，无须全部成交才通过持续报单测试。该项主委托不会自动清理；柜台拒单、连接异常、交易日变化或用户停止时不再续发，最后一笔回报及收尾核对也检查这些条件，不能因报单数量已满而判为通过。收尾回报核对可能额外等待。仅测试 SDK 实际支持交易的合约类型，不预先保证套利合约可用。

非法输入只选 UserID。样例用转义字符显示，避免换行／退格改变日志排版。截图应包含客户端拦截记录及“未发送柜台、原连接保持”的证据；需要代码截图时，打开 [实际登录校验代码](../ctptest/login_validation.py) 中的 `validate_user_id` 与 `build_ctp_account`。不构造不存在的柜台拒绝回报。

## 结果判定

| 结果 | 含义 |
| --- | --- |
| 通过 | 已取得该项所需的实际回报或本地拦截证据 |
| 未通过 | 实际状态、错误类型或错误码不符合目标 |
| 待环境准备 | 账号、持仓、资金、时段或其他条件未满足；不计为通过 |
| 结果待核对 | 提交未知、回报超时、错误码缺失或委托关联不完整 |
| SDK 限制 | 实际请求被 SDK 的行为阻挡，无法取得该项所需柜台证据 |
| 已停止 | 前台后续步骤已停止；已发出的请求仍需核对 |

`SUBMITTED` 不是柜台接受、成交或撤单成功。开平仓须双向全部成交；柜台错误须关联到目标委托，原文中的明确非零码值符合目标，配置预期码时还须匹配。拆单需所有子单满足判定，不能用一笔成功覆盖其余未确认状态。

## 委托与停止规则

开平仓两笔提交后转为“等待成交”，柜台错误请求提交后转为“等待回报”，立即释放操作按钮。后台回报继续关联原测试运行，旧回报不覆盖同项目较新运行的列表状态。超时结束本次判定，不自动改价或重发，后续真实回报仍写入原运行日志。

普通开平仓和柜台错误测试的主委托不会因完成、超时或停止而自动撤销。撤单、统计、预警和暂停恢复流程中明确创建的辅助单，仅在本工具拥有、已确认可撤且撤单结果未处于未知状态时尝试清理。意外成交或清理失败按实际状态显示，不能伪造撤单成功。

停止只阻止当前前台尚未发出的步骤，不取消此前后台委托。退出或断开不会自动平仓或撤销账号全部交易。需要撤销本工具挂单时，可明确执行“单笔撤单”。

## 统计口径

计数按环境、账号、交易日隔离，只统计 ctptest 实际发出的请求。每个 SDK 子单的 `SUBMITTED` 或 `UNKNOWN` 计一笔，未知数量另外标注；本地拒绝、明确未发送及撤单空操作不计。快照重放不重复计数，其他客户端委托不计入本工具统计。

同次运行重连保留统计；重开应用清空记录与计数。同一运行跨交易日重新累计。辅助单清理发出的撤单同样计数。达到或超过阈值只预警，不自动停止交易。

## 截图与证据保存

使用系统截图工具，确保画面包含测试名称、实际委托参数、相关回报、错误原文及结论；必要时补充滚动区域截图。日志时间为上海时间。仅显示 SDK 实际提供的字段，不把快照包装为逐条原始 CTP 回调。

日志目录包含本次会话的 `ctptest.log` 与 SQLite 结构化记录。请在退出前另行留存材料；下次启动不会恢复上次记录。界面显示完整账号，发布到 Issues、教程或公开仓库前请脱敏；不要公开凭据或原始数据库。

逐项真实柜台验收记录使用 [验收检查表](../ACCEPTANCE.md)。SDK 替身结果与真实柜台验收分别保存，不能用替身记录制作正式验收证据。

## 范围与下一步

本项目实现上述 29 项，未实现重复报单、批量撤单等选测；暂停相关行为集中在“暂停与恢复”。最终项目及材料要求以接收测试的期货公司为准。

遇到不符合预期的拒单，先查看 [常见错误与 SDK 边界](troubleshooting.md)。继续开发自己的 Python CTP 程序，可阅读 [exsdk 交易文档](https://skyzhi.com/docs/trading?utm_source=github&utm_medium=docs&utm_campaign=ctptest&utm_content=trading)。
